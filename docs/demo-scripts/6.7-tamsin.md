# 6.7 High utilizer — "Tamsin"

## Purpose

Show the cost side: a woman who taps "I need help now" at most check-ins, asks for callbacks,
writes notes and saves many questions, each of which is human-routed on entry. Show the two
free-text modes on the same saved question: with scanning off (the shipped flag) the note reaches
a clinician on the same-business-day target with the crisis line and named contact beside the
field; with scanning on the same entry also renders the full-screen instruction and creates an
Urgent item. Show the canned question organizer grouping her other questions without answering
them, and her minutes in the budget owner's top decile.

Not shown to women. Practice stakeholders: default. Open with the cross-scenario block and close
with the paired questions.

Say aloud, at step 5 (scan off): "In this mode a note that mentions self-harm reaches a clinician
on the same-business-day target; the clinical owner chooses this by leaving scanning off, and the
crisis line is on the screen either way."

## Persona

Tamsin, adult, English, commercial insurance, twins, NICU stay. Delivered Monday 2026-01-26;
enrolled by the coordinator before discharge on day 1; she set the NICU status herself the same
morning. Sharing category clinician and coordinator; contact windows all day.

## Branches and starting clock

| Branch | Starting clock | What is on screen |
|---|---|---|
| `tamsin_scan_off` | Fri 2026-02-13 16:11 (day 18) | The flagged saved question created a Needs-review item a minute ago |
| `tamsin_scan_on` | Fri 2026-02-13 16:11 (day 18) | Same history; requires `free_text_urgency_scan: true` in `config/freetext.json` (see below) |

The scan flag is config under the clinical safety owner's name (FR-17). It is off in this build,
so `tamsin_scan_on` runs the same commands and shows the scan-off behaviour; its description says
so. To show the scan-on branch live, set `free_text_urgency_scan` to true and
`free_text_urgency_scan_set_by` to the owner's id in `config/freetext.json`, rebuild and
restart, then load `tamsin_scan_on`. The scan-on outcome is asserted in
`src/seed/tamsin.test.ts` against a config with the flag on, so both branches are verified
regardless of the flag in force.
