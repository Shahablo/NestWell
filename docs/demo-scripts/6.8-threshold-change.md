# 6.8 Optional: threshold change

## Purpose

Show that the placeholder screening threshold is configuration owned by a named clinical owner,
that the app refuses to run on an invalid change, that the banner clears only when the owner
signs the file, and that the same persona history routes differently under the new threshold
(decision D5). Optional; practice stakeholders only; not shown to women.

There is no seed branch for this scenario: it is a config edit and a restart. Config is data,
not code (FR-61), so nothing else changes.

## Persona

Priya (6.2): her day-14 screen scores exactly 10, the shipped placeholder threshold.

## Starting clock

Any. Load `priya` and set the clock to Thu 2026-04-02 12:00 before and after the change.

## Steps

| # | Actor | Screen | Action | Expected result |
|---|---|---|---|---|
| 1 | Founder as clinician | Practice → Screening; Admin → Validation | Before the change, note the thresholds banner and the placeholder label on the instrument step. | Banner: thresholds unconfirmed (`thresholds_confirmed_by` is null); Priya's day-14 screen is at threshold and created a Needs-review item (FR-28, FR-30). |
| 2 | Clinical owner (a `staff_user` with role clinician and permission `config_approver`, `ob-1` in this build) | File `config/instruments/epds.json` | Live. Set `threshold_positive` to 11 and `thresholds_confirmed_by` to `"ob-1"`; commit under their name. This build stores config as JSON where the requirements say YAML. | The change is a git commit with the owner's name (FR-61). |
| 3 | Founder | Terminal | Run the validator and the harness: `npm run validate`, then `npm test`. | The validator prints zero problems; the harness lists the cases that changed. In this build the harness is the test suite: `src/seed/priya.test.ts` fails on the day-14 positive-screen item and the intervals until the expected outcome is confirmed by updating the test, which is the "changed, unconfirmed" list (FR-31). |
| 4 | Founder | Restart the app; Admin → Validation | Rebuild and restart. | The thresholds banner clears and names the confirming user (FR-28). |
| 5 | Founder as clinician | Practice → Queues → Needs review; Screening | Load `priya`, clock Thu 2026-04-02 12:00. | Under the new threshold her score of 10 is below threshold: only the coping item exists; the positive-screen item and the day-14 intervals are gone; the week-6 score of 12 still creates one. The persona history did not change, the routing did (D5). |
| 6 | Founder as admin | Admin → Inventory (content and rules export) | Show the export. | The instrument version, `thresholds_confirmed_by`, the FR-17 and FR-30a flags and the AI state are listed (FR-65). |

## Expected events

`config_changed` is recorded from git metadata when the loader supports it; this build validates
at startup and logs nothing to the event store for a config change. Priya's stored events are
unchanged; the projection derives no `positive_screen` item at day 14 under the new threshold
because the item was created by a service at seed time and the branch must be reloaded to
re-run the rules against the new config (Admin → Scenarios → Load).
